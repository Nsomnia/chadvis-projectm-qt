## The hard gates (unchanged by this sweep)

* ~~Mutations need our own capture~~ — **superseded 2026-10-30 by the owner grant**
  (AGENTS.md "Authorized live work"). A mutation needs **our own observation**: a call
  this client or this agent made against the live service while signed in as the account
  owner. That observation may be recorded at `[T1]` without a separate capture artifact.
  A `[LEAD]` third-party body is still a lead, never a request builder, and a route whose
  failure mode is a wrong object or a silent partial write still needs a runtime check
  before it is wired.
* **No new `CapturedHosts` host without our own observation.** Names the register brings
  (`audiopipe`, captcha hosts, the unknown prepared-download host, CDN variants) gain
  **nothing** in `src/suno/CapturedHosts.cpp` on a document alone; a host this client has
  actually talked to, or an agent probe with the owner's session answered, is an entry.
* **Studio multitrack export is out of scope** — the `render-state-multitrack`
  arrangement-state product is a Studio flow this client deliberately excludes.
* **A JWT `_sid`/session-check and every auth surface is untouched** by this sweep —
  T0339–T0344 own that space.

## Method: grep, do not guess

Statuses below were established by grepping `src/suno/` + `src/qml_bridge/` on
2026-10-27: the call sites actually referencing `endpoints::*` (24 constants in
production code), the `SunoLibraryMutations` verb set (11 wired routes,
`enabled_{false}` per T0011), `SunoDownloader` (progressive `media_urls` only), and
the bridge stubs (`SunoBridge::generate()` refuses with a message — no submit, no
poll). A constant with zero call sites is **declared-unused**, not "built".

## Module placement (extend, do not add)

No new module without a reason. The owner of each family is an existing service:
