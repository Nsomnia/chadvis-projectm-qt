This is the canonical changelog for ChadVis. It follows [Keep a Changelog](https://keepachangelog.com/en/1.0.0/) and [Semantic Versioning](https://semver.org/spec/v2.0.0.html). ## [Unreleased]

### Added

- **Recordings can now carry the karaoke track as a real subtitle stream.** `LyricsBridge::assDocument()` already produced a complete `.ass` document; it is now muxed into the encoded file, so a player shows selectable, per-word karaoke without the user handling a sidecar. **Container constraint, measured rather than assumed:** `avformat_query_codec` returns `1` for Matroska and `0` for MP4, MOV, WebM and AVI on this FFmpeg, so **only MKV can carry ASS**. The gate is therefore load-bearing rather than defensive: without it, MP4 — the default output — would gain a subtitle stream that `avformat_write_header` rejects, failing *every* MP4 recording. That was verified with standalone probes rather than from the `ffmpeg` CLI, because the CLI fails in `init_muxer`'s tag lookup at write time, a different code path from the query. **There is deliberately no `mov_text` fallback**: MP4 answers `mov_text=1, ass=0`, so its only text codec is 3GPP timed text with no override-tag syntax — a `\kf` cue would be flattened to plain text, i.e. the feature appearing to work while being precisely what it must not be. `initSubtitleStream` returns `void` by design, so no subtitle outcome can ever fail a recording: no lyrics, an unusable container, or a malformed document all yield a normal playable file with a `LOG_INFO` saying why the track was dropped. Cues are emitted on the **video clock** rather than up front, because writing a three-minute lyric sheet in one go would exceed `av_interleaved_write_frame`'s 10000-packet interleave default and return `EAGAIN`, silently dropping cues. `AV_DISPOSITION_DEFAULT` is set because Matroska's `mkv_default_mode` marks a subtitle *not* default, so without it the track ships switched off and nobody sees it.

### Fixed

- **The recorder reported a successful start it never had, and "completed" files it failed to write.** Two independent lies in the one component whose entire job is producing a correct file. `VideoRecorderThread::start()` returned `void` and swallowed an `ffmpeg_.init()` failure, so `VideoRecorderCore` set `state_ = Recording` and returned `ok()` regardless — an unwritable output directory, a missing codec, or a bad container/codec pairing produced a UI showing an **active recording** with a running timer, no file, and no error. It now returns `Result<void>`, and only enters `Recording` on genuine success, setting a **reachable, recoverable `Error`** state and zeroing the counters *before* announcing the transition (the bridge snapshots the stats at exactly that moment). A state nobody could recover from would have been a worse bug than the one being fixed, so `start` and `stop` both accept `Error` and perform normal transitions. Separately, `writePacket`'s return was discarded by both callers while `framesWritten` incremented regardless, so **disk-full at 90% produced a truncated MP4 that opens and plays to the break point and was reported `Completed`** — worse than a failed recording, because it is a plausible-looking one. The muxer return is now classified `Written` / `Backpressure` / `Failed`; `Failed` sets a sticky flag, the loop stops producing and reports once, and `stop()` names the likely cause. **The judgement call: `EAGAIN` is backpressure, not failure.** Folding it into failure would mark a merely-slow recording as broken — the same class of lie in the opposite direction — so a backpressured packet is not counted (it genuinely is not in the file) but is not treated as damage, and it logs once rather than once per frame. Also fixed: both `av_frame_get_buffer` returns, both `swr_*` returns (discarded while `swrCtx_.get()` was dereferenced by the very next call), and `av_write_trailer` — without which an MP4 has no `moov` atom and a file that will not open. **A latent null-deref surfaced en route:** after a failed init the destructor's `stop()` reached `av_interleaved_write_frame` on a context with either no `pb` at all or no header written, so the `headerWritten_` gate now covers the flush and trailer paths too. Four of the five production fixes are guarded by reasoning about what cannot fire rather than by a test, because there is no portable way to induce OOM or a null resampler in-process; the two behavioural tests are real, and both fail on the old code.
- **Every karaoke cue would have been written 100x too small.** The centisecond→millisecond conversion was `cs / 10`, where `kMillisecondsPerCentisecond = 10` names a **multiplication**. So a two-second cue was written as 20 ms, and a three-minute song's entire lyric sheet would have collapsed into its first 1.8 seconds, stacked on itself. Two sites divided — the cue's own `pts`/`duration` and the video-clock interleave gate — so they **agreed with each other and disagreed with reality**, which is why nothing upstream could see it, and `timingsMs[0].first == 0` passed by coincidence because `0/10 == 0*10`. The conversion is now a single named `toMilliseconds()` used by all three call sites. **Only an exact-value assertion could have caught this class**: "the duration is non-zero" or "roughly 2 s" would have passed on every version of the bug. Caught before it could ship.
- **A broken test reader was masking that bug, by cancelling it out.** The recorder suite's `readEncodedStreams` had two defects that composed: a missing `continue` let audio and video streams fall through into the subtitle block, so *every* file appeared to have a subtitle track, and a forward-only `av_read_frame` cursor was drained once per stream, giving the first stream the whole file and leaving the real subtitle stream empty. Six tests failed; the reader, not the muxer, caused all of them. Worth recording as a general trap: **a broken reader cannot distinguish "the muxer wrote nothing" from "the reader read nothing"** — and here the reader's own unit error happened to cancel the writer's 100x error, so the test compared two wrong numbers and saw something plausible. The MP4 failure's own assertion text said "the muxer declared an ASS stream in an MP4", which was the wrong conclusion entirely; the absence assertions now report the actual stream table on failure so the reader-vs-muxer question answers itself in one look.
- **The ASS assembler moved out of the QML bridge.** `src/recorder/` must not reach up into `src/qml_bridge/`, so `toAssDocument` now lives in `src/lyrics/LyricsData.{hpp,cpp}` under the existing `LyricsExport` namespace and both the bridge and the recorder call it — still exactly one assembler. `VideoRecorderFFmpeg.hpp` names no lyrics type and takes the document as opaque bytes. Production wiring runs `RecordingBridge → VideoRecorderCore → VideoRecorderThread → init(settings, assSubtitle)` with every hop defaulted to `{}` so all pre-existing call sites are untouched, and the bytes are copied into the encoder before the `JThread` is created so no borrowed `string_view` can cross the thread boundary.
- **An opt-in ThreadSanitizer lane, so two shipped sanitizer claims become reproducible.** The changelog asserted "AudioAnalyzer concurrency tests pass under ThreadSanitizer" and the backlog credited the PFFFT fix with "normal and ThreadSanitizer tests" — but there was no `-fsanitize` anywhere in `CMakeLists.txt`, `cmake/`, `tests/` or `scripts/`, and all 29 `sanitize` matches in the tree were `sanitizeFilename`. Both claims described an ad-hoc build that was never captured, which is not a verification a future session can check. `CHADVIS_SANITIZER` is now a cache option in `cmake/Compiler.cmake`, paired with `cmake/tsan.supp` and a `TSAN_OPTIONS` block on the ctest entries. Built and run: **320/320 targets, zero errors, the lane executes, and every test passes under it.** Three design points were load-bearing and all were measured rather than assumed. It is a **cache option, not a target**, because `unit_tests` links `libproject_lib.a` holding all app code — a `unit_tests_tsan` target would link uninstrumented objects, report nothing and exit 0, which is a false-negative generator worse than having no lane at all. Darwin defaults to `abort_on_error=1`, so a ctest entry without `TSAN_OPTIONS=abort_on_error=0` dies with SIGABRT on the *first* finding; `halt_on_error=0` does **not** suppress it. And `CMAKE_OSX_SYSROOT` is actively unsafe here: adding the SDK the compiler already reports for itself drops `/usr/local/include` from `/usr/bin/c++`'s search list, stripping the project's only route to fmt, spdlog, toml++, glm and taglib.
### Fixed

- **A test that blocked a worker thread could turn any failed assertion into an unrecoverable 300-second hang.** `concurrentRestoresCoalesceInsteadOfDoubleReading` blocks the credential backend in `releaseBackend.acquire()` and released it only after several `QVERIFY`s. If one of those failed, `QVERIFY` early-returned, the release never happened, the worker thread stayed blocked forever, and `~CredentialStoreWorker`'s `quit()` + `wait()` hung — the `quit` cannot take effect because the event loop is blocked *inside* the lambda. The real one-line assertion message was buried under a QTest timeout and SIGABRT. **This is build-independent:** any test that holds a worker thread in a blocking wait must arm its release before the first assertion that could fail, because `QVERIFY` is not cleanup and a joining destructor converts a missing release into a hang rather than a failure. Fixed with a scope-guard that releases on every exit path. The sanitizer lane also runs ~5–20x slower, so wait budgets now scale from a `CHADVIS_SANITIZER_BUILD` definition instead of being hard-coded, keeping the normal build's fast timeouts.
- **Suno credential restore has a dedicated readiness worker.** Reading the keychain used to race startup: a surface that asked early got an answer that was really a guess, and the guess was indistinguishable from "no credentials". Restore reads now coalesce on a worker that never drops a caller — a second or third requester attaches to the read already in flight rather than queueing a second one and receiving a different answer — and the Library and Explore surfaces wait for **definitive** readiness instead of proceeding on "not yet". The distinction matters because a keychain round trip is slow enough to lose a race and fast enough to look like a hit: without the gate, a cold start presented an empty library that then filled in underneath the user, with no error and no signal that anything had happened.
- **API master: `POST /v1/client/verify` is resolved to POST, and its purpose is now known.** The route was carried as an unresolved method/contract conflict with a companion Appendix A row; five direct observations in the 2026-08-25 capture settle both halves. It is **POST**, with a form body of `captcha_token` + `captcha_widget_type=invisible` + `captcha_action=heartbeat`, and a **204 No Content** response. It is a captcha-gated Clerk session heartbeat, corroborated three independent ways: the form field is literally `captcha_action=heartbeat`, the Clerk instance reports `captcha_heartbeat: true`, and the calls sit 1–8 minutes apart with no other traffic on the instance to explain them. The useful part of the resolution is negative and now **proven** rather than merely prudent — a 204 with no body cannot return a bearer, so this route definitively cannot be used for token refresh, which is what the "leave the Clerk `tokens` route unwired" conclusion rested on. The route stays `not-in-code` until something needs it. `/v1/verify` is a **different, still-unobserved** route and is kept separate in four places so a future reader does not merge the two on the shared prefix.
- **API master: two captcha systems that were previously conflated are now distinguished.** The Clerk auth captcha is **Cloudflare Turnstile** — `captcha_provider: "turnstile"`, `captcha_heartbeat: true`, `captcha_widget_type: "smart"`, plus a managed and an invisible sitekey — and the tokens on the wire carry Turnstile's `1.<payload>.<hash>` shape, which rules hCaptcha out for that route. The suno.com web sign-in UI captcha is **hCaptcha**, recorded from the sanitized recon's `api.hcaptcha.com/getcaptcha/…` on the session-recovery pages. The generation captcha is also Turnstile rather than hCaptcha: `TURNSTILE_GENERATION_CAPTCHA_VERSION = 2` with `FORCE_ENABLE_CAPTCHA = false`, and the hCaptcha constant in the client bundle is marked legacy. One rule is now recorded in the master, and it is the part most likely to be re-learned the hard way: **naming a captcha provider adds no captcha host to any allowlist.** An earlier pass at this same work closed by asserting that the generation provider was "still unstated"; that assertion was wrong and is corrected here rather than left to be found again.
- **API master: six OAuth providers are enabled server-side, not just Google.** `GET /v1/environment` reports `identification_strategies` covering Google, **Facebook, Apple, Discord and Microsoft**, an Apple-token strategy and phone number, with `password: "on"` and `preferred_sign_in_strategy: "otp"`. Recorded strictly as an instance-configuration fact — **not** an endorsement, and **not** evidence that any additional provider works through a native loopback callback, which is a separate capture question and the one that actually gates shipping. Apple Sign In is worth recording on macOS specifically because `AuthenticationServices` can produce the `oauth_token_apple` credential natively and would remove a browser round trip; that is a design decision *enabled* by evidence rather than evidence of a design, so it stays in the backlog and not in the master.
- **API master's document map named neither of the two sections it had grown.** A reader could follow the section pointer to the OAuth analysis document, come away understanding the cookie flow, and never learn that the credential *shapes* were documented at all — §3.3 and §3.4 were reachable from inside the document but advertised by none of the entry points. Both the master's document map and `docs/suno_api/README.md` now name them, because the "one fact, one owning document" rule only works if the map is the index and the index is current. Worth recording how it was caught, since both detectors were wrong in **opposite** directions: a first link-checker reported the new anchors broken, and a second reported the long-standing `#appendix-a--explicit-conflict-register` anchor broken. The first collapsed whitespace where the slugger keeps one hyphen per space; the second assumed em-dash stripping left a single hyphen. An anchor checker is exactly as trustworthy as its slugger, and neither failure was visible in the documents — only in the tool.
- A GL-backed integration suite for the recording pipeline, registered as its own `integration_gl_tests` ctest entry. It runs against a real window, context and projectM, and proves the destination projectM actually draws into, that a bound FBO is ignored, that the capture is non-empty and correctly oriented, that a differing record resolution is scaled, that the live native window captures pixels through its own render timer and buffer swap, and that a 45-frame H.264 encode decodes back to a lit picture. The headless `integration_tests` entry still runs offscreen, where these skip with a stated reason — the macOS offscreen QPA plugin cannot create an OpenGL context at all, so a green headless run would prove nothing.

### Changed

- **Settings auto-save on a 2 s debounce with an explicit save on close**, instead of writing the whole config synchronously on every edit. `SettingsBridge` arms a 2000 ms timer and flushes when the window closes, so dragging one slider is one write rather than one per frame, and closing the window cannot lose the last edit. The explicit close-time save is the half that matters: a debounce with no flush trades a write storm for a data loss, and the loss stays invisible until a setting is mysteriously reset at the next launch.
- **`OverlayBridge` saves on a 2 s debounce and flushes on destruction**, so pending overlay edits are never lost on shutdown. Overlay edits had the same two failure modes as settings edits — a write per change, and a final change dropped when the process ended — and the flush is explicit for the same reason.
- **`UIConfig` gained `expandedPanel`, `sidebarWidth` and `drawerOpen`**, parsed, wired bidirectionally, and shipped in `config/default.toml` as `expanded_panel` / `sidebar_width` / `drawer_open`, so the shell's layout state survives a restart instead of reverting on every launch. Config parser defaults now derive from a default-constructed `ConfigData` rather than restating each literal, which gives one source of truth: a field added to the struct is parsed with the right default, with no second edit that can disagree with the first.
- **`[karaoke]` is now parsed and serialized.** The karaoke config existed in `ConfigData` and was reachable through `SettingsBridge`, but nothing wrote it or read it back, so karaoke settings were neither durable nor round-trippable.
- **`SettingsPanel.qml` split from 526 LOC into 8 per-category panels.** Recorded as completed work only. This is the *orphaned* settings path — the live shell runs `SettingsWindow.qml` plus `settings/*Page.qml` — and the duplication between the two systems is a separate open item that this split neither fixes nor worsens; splitting the dead copy is not the same as deleting it, and the split was worth doing on its own terms.
- **The record button's highlight was inverted against `RecordingBridge::isRecording`**, so the control lit while *not* recording and went dark for the duration of a recording. The `text` and `icon` bindings on the same button were already correct, which is what made the failure a highlighted button reading "Stop" during an active session — the one piece of UI whose state is load-bearing during an operation that cannot be undone, showing the wrong state.
- **~20 stale `cmake/` modules removed.** `cmake/` now holds 7 modules in active use — `CPM.cmake`, `Compiler.cmake`, `Dependencies.cmake`, `FindProjectM4.cmake`, `Install.cmake`, `Sources.cmake`, `TargetSetup.cmake` — and every one is included by the top-level `CMakeLists.txt`. **Do not delete them**, and more generally do not read a `cmake/` directory that looks untidy as evidence that its contents are unused: a removed module fails at configure time rather than at review time, and a short directory is not the reason any of these seven stayed.
- **Two dead declarations removed:** `PresetBridge::cachedPresets_`, which had zero readers once the preset snapshot work landed, and `PlaylistItem::valid`, a flag nothing ever read — so a `false` there would have been silently ignored by every consumer while reading as an enforced invariant. Deleting the field is what removes the ambiguity; a guard that is never checked is worse than an absent one, because it invites callers to branch on it.
- *(The `[karaoke]` and settings/UI maintenance entries above are folded in from a backlog reconciliation, where completed items that had no changelog writeup were preserved rather than deleted.)*

### Fixed

- **Preset scanning walked the entire preset library on the GUI thread at startup.** `PresetManager` gained `scanAsync` / `rescanAsync` / `setPublishContext` over **shared generations**: every scan builds a fresh vector and *swaps it in*, so a published generation is never cleared, resized or refilled in place, and a `const PresetInfo*` taken before a rescan stays valid instead of dangling into recycled storage. The worker is a `vc::JThread` parked on a condition variable — the `VideoRecorderThread` pattern — rather than a moved-`QObject` `QThread`, because `PresetManager` is a *value member* of `pm::Bridge` and a `QThread` has no valid move. Requests coalesce latest-wins, so a burst of N rescans costs at most two directory walks, and a failed scan **retains the previous generation** instead of silently emptying a working library — the failure mode of a rescan is "my library is still there", never "my library vanished and I did not notice". The per-file `std::regex` was hoisted out of the scan loop, where it was compiling a grammar per preset — the dominant cost once the stat storm is paid — and replaced by a provably-equivalent `find('-') == npos` early-out. The synchronous `scan()` is **kept on purpose**: `pm::Bridge` reads `empty()` and `selectByIndex(0)` immediately after it and never sets a publish context, so it never starts a worker at all. A pinned-generation test fires 8 rescans and asserts the old pointers stay valid while a new generation appears at a different address, which is the invariant the copy-on-publish design exists to provide.
- **The startup preset list would have been permanently empty.** `PresetBridge::connectSignals()` was declared, defined, and called from nowhere, and because `qmlEngine_->load()` runs *inside* `init()`, QML's one-time `model:` binding evaluated before any async scan could publish — the list would have stayed empty for the life of the process while the scanner reported success. Wiring now happens in an idempotent `attachManager()` called from the constructor, so it is correct whether it is reached once or twice. This is the `AGENTS.md` §3 failure class — a declaration that reads as a working feature and is not — and it was surfaced *by* the fix above rather than independently: moving the scan to a worker alone would have shipped an empty library that no test could see, because the two defects are individually harmless and jointly fatal.
- **`Playlist` had no thread contract, and a mutex would have been the wrong fix.** It now carries a `const std::thread::id ownerThread_` with `assertOwnerThread()` on every public method — deliberately **not** a mutex, because a lock would *mask* an off-thread writer while `PlaylistBridge`'s row bookkeeping silently rotted underneath it, whereas the guard turns a heisenbug into a log line and an abort. The read API already returns values rather than borrowed views, so `PresetManager`'s shared-generation machinery has no reason to be replicated here; if a second thread ever does appear, the correct move is to marshal to the owner thread with `QMetaObject::invokeMethod(..., Qt::QueuedConnection)`, or to add exactly one coarse mutex **with every emit moved outside it**, since `currentChanged`'s live subscribers re-enter the playlist through the engine. **The backlog premise "UI and audio threads" was wrong twice:** the analyzer `JThread` was deleted when `spectrumUpdated` lost its last consumer, and `QMediaPlayer` is GUI-thread-driven — a `QObject` created in `init()` whose backend decodes on its own threads but delivers every signal to the object's thread. `DownloadQueue` has **no threads at all**: it is a plain `QObject` whose `setMaxConcurrent(3)` bounds in-flight HTTP replies multiplexed onto a single event loop, which nothing in its header says and which makes `addAndPlay` look dangerous to any reader who has not opened the implementation. **Two limitations recorded rather than papered over:** `assertOwnerThread` proves thread *affinity*, not re-entrancy safety — a slot re-entering the playlist from inside an emit is same-thread and passes, which is the current design working rather than a hole; and the `assert` compiles out under `NDEBUG` while the distributable build is Release, so a Release binary logs the violation and then walks into the race. That fail-loud-but-continue behaviour is accepted as the lesser evil against a false negative; a hard Release failure would need `std::terminate()`, not `assert`.
- **`LyricsSync` had two independent entry points into one read-modify-write.** The `QTimer::timeout` lambda and synchronous direct calls from `loadLyrics`, `seek` and `jumpToLine` all reached `updatePosition`, which is a read-modify-write over `smoothedTime_` (a `lerp`) plus a compare-then-write over `currentPos_` — so the two paths double-applied smoothing for a single audio instant and could drop or duplicate a `lineChanged` / `wordChanged` edge, in a class with no synchronization of any kind. `trackChanged` was additionally connected `Qt::DirectConnection` while its `stateChanged` sibling correctly used `QueuedConnection`, so a full state reset could run outside the event loop's ordering guarantees. The `QTimer` is now the **sole** writer, via a one-shot seed drained by a new public `syncNow()`; `seek` and `loadLyrics` seed rather than apply, and `trackChanged` is queued. A mutex was **deliberately not added** — two writers plus an unguarded `lyrics_.vector` would be strictly worse than the single writer now in place, and a lock would hide the second writer rather than remove it. Two subtleties are load-bearing: a seed must *snap*, which the drain achieves by pre-setting `smoothedTime_` so the lerp degenerates, or `seek` stops being exact and a mid-playback `loadLyrics` ramps from 0 instead of snapping; and `seek` with a null `AudioEngine` never drains on its own, which is what forced `syncNow()` to be public rather than a test-only backdoor. `AudioEngine::positionChanged` remains unconsumed and lyrics still poll — unchanged behaviour, and adding the second trigger would invite a second writer of exactly the state this change made single-owner.
- **Both `avcodec_alloc_context3()` results were unchecked.** A codec-allocation failure on the video path left a null `videoCodecCtx_` that setup code immediately wrote `width`, `height`, `time_base` and `framerate` through; the audio path had the identical shape with `sample_rate` and `bit_rate`. A resource exhaustion therefore became a null dereference mid-setup instead of an error the caller could report. Both allocations are now checked and return a named error alongside the existing stream-allocation checks.
- **`Playlist::loadM3U` followed relative entries out of the playlist directory.** A relative entry in an M3U is resolved against the playlist's own location, and nothing constrained the result — so a downloaded, synced or hand-edited playlist could name a file anywhere the process can read and have it silently appended to the queue, with nothing in the UI saying where the audio came from. Relative entries are now weakly canonicalized and rejected when they resolve outside the playlist directory.
- **The session selector re-derives the active session id from the access token's `sid` claim** rather than from `response.last_active_session_id`, which read as a deviation from the API master. The 2026-08-25 capture settles it: all four identifiers are the same value — `last_active_session_id` == `sessions[0].id` == the JWT `sid` claim == the `{sid}` path segment of the `touch` request — so the substitution is **corroborated** rather than corrected, and the released 1.1.0 security note that session selection requires an exact `last_active_session_id` match is unchanged in substance. Deriving from the token drops a dependency on a response field the request does not otherwise need, and one source for the id is one fewer place for four copies to disagree. **Honest limit:** this is one capture containing a single session, so it corroborates the substitution without proving it for a multi-session account, and the master's "do not assume array position" rule stands untouched.
- **Downloading a batch of clips hijacked playback.** `SunoDownloader::processDownloadedFile` was a one-line alias for `addAndPlay`, which appends to the playlist and `jumpTo`s — so fetching N clips to disk audibly played them one after another and interrupted whatever was playing. The completion hook now reads a requested `DownloadAction` out of the pending record and only enqueues for an explicit play request, `SunoBridge` gained save-only `downloadClip`/`downloadClips` alongside the untouched `playClip`, and a `clipSaved(clipId, path)` channel reports the result even when the file was already on disk and no transfer occurred. The single-clip download-and-play path is preserved byte-for-byte, including the on-disk shortcut, and `SunoController` needed no change. The headline test asserts playlist size and current index **directly** rather than inferring from signals, because the pre-fix defect was a mutation, not a missing notification. Three further real defects fixed en route: a second request for an in-flight clip overwrote the live request's pending record and then erased it, so the transfer finished with no tag, no sidecar, no announcement and no play — it now escalates instead; `tagAudioFile` dereferenced an ID3 tag pointer unchecked while the queue renames the `.part` into place on any HTTP 200, so a non-MPEG payload could reach it; and same-titled clips could overwrite each other, now disambiguated with a sticky per-clip-id suffix. `download()` also returns which fail-closed predicate fired, so an unplayable clip is a diagnosable error rather than a dead button. The `content_type == "mp3"` filter itself is **deliberately unchanged** — widening it is an evidence question about whether Suno serves Opus without a web-side decryptor, not a code change.
- **The LRC writer emitted remote metadata unescaped, and the repo's own parser then forged a lyric out of it.** This was data corruption, not tidiness. `fromLrc` matches timestamps with an *unanchored* `regex_search` and ignores metadata, so a title of `Song [00:30] Live` written as `[ti:Song [00:30] Live]` came back as a phantom lyric line at 30 seconds whose text was ` Live]` — measured by running the parser's own pattern. LRC defines no escape syntax, so this is a *substitution* rather than an escape: `[`→U+FF3B and `]`→U+FF3D, with CR/LF collapsed to space. The design changed on measurement rather than on principle: substituting only `[` left the file with 3 opening but **5 closing** brackets, unbalanced, with a surviving `]` a tag reader could still truncate at. Substituting both gives 3/3, which makes "every remaining ASCII bracket is a real tag delimiter" a checkable invariant. A test round-trips the file through the real parser and asserts no phantom line appears.
- **`std::llround` on a possibly non-finite remote timestamp was undefined behaviour in the SRT and LRC writers.** All three lyric formatters now share one `toTimeUnits(seconds, unitsPerSecond)` helper with an `std::isfinite` guard. The unit is a **parameter, not a shared constant**, and that is load-bearing: SRT is milliseconds while LRC and ASS are centiseconds, so routing SRT through a centisecond helper would quantise twice — `1.4567s` is `1457ms` scaled directly but `1460ms` via `146cs` — silently changing shipped bytes. Equivalence was proven by a differential test of the old and new expressions as **actual C++** over 3,097,435,587 finite floats with zero mismatches, plus a bitwise check that the scale constants equal the originals.
- **An SRT cue could be emitted backwards and therefore silently discarded by players.** The widening rule was `end > start ? end : start + 1` on the raw `f32`, so a non-finite value slipped past it — `+inf > 1.0` is true — and only became zero inside the formatter, yielding `00:00:01,000 --> 00:00:00,000`. A player drops a cue whose `End <= Start` outright, so the file looked fine and the line simply vanished. The floor is now applied in the **output** unit, mirroring the ASS writer: inert for every finite well-formed line, so no golden byte moves, but it also stops a NaN start from discarding the line's real end time.
- **`LyricsSync::getUpcomingLines` could spin essentially forever, and return a corrupted result when it did.** It looped `for (i = 0; i < count; ++i)` with no early exit, so an oversized count ran 2⁶⁴ iterations. A 16-bit simulation of the pre-fix loop shows it is slightly worse than a hang: for an anchor of 1 or more it *does* eventually return — the correct lines *plus one spurious duplicate* of an already-passed line — and a duplicate is worse than a hang, because a hang is noticed. Three decisions are load-bearing: `av_rescale_q` rather than a hand-rolled division, because truncating biases every frame one tick early *and* accumulates while nearest-integer is bounded by half a tick with no drift; the origin is normalised to PTS 0, because a `steady_clock` reading is microseconds since boot and handing that to a muxer inflates the reported duration through the MP4 edit list; and monotonicity is guaranteed twice over, by a `lastVideoPts_ + 1` floor and by a no-timestamp path that steps by the last observed real interval rather than acting as a counter, so extrapolation error cannot accumulate. **Stated limitation:** when the renderer outruns the nominal record fps, consecutive frames collapse to one tick and duration tracks frame count rather than wall time — pre-existing behaviour, unchanged, and already the subject of a `startRecording` warning; fixing it is frame-rate conversion. ## [1.1.0] - 2026-09-26

This release finalizes the `v1.1.0-BLEEDING_EDGE` line and is the first version whose source, executable, and release metadata are sourced from the same `version.txt` value.

### Added

- Suno-first desktop shell with Library, Create, Listen, Video, and standalone paged Settings surfaces.
- Capture-backed Explore, Notifications, Library pagination/filtering, account/billing surfaces, and the captured three-leg `.m4a` upload transport.

- Offscreen QML integration smoke that requires a visible/exposed root and a non-null rendered frame.
- Focused epoch, media/origin, header, persistence, and audio-concurrency regression coverage.

- Credential/request epochs fence queued work, retries, auth waiters, and tracked replies across sign-out, replacement, and auth loss; direct uploads cancel on credential invalidation.
- Settings credential ownership is centralized in `SunoClient`; manual edits are debounced off the GUI thread and clearing keeps memory and durable storage coherent.
- Remote artwork, MP3 media, and direct upload URLs are restricted to exact capture-proven HTTPS origins with manual redirects.
- Clerk session selection requires an exact `last_active_session_id` match; undocumented Browser-Token synthesis and automatic `/tokens` fallback are disabled.
- Mutation POSTs are not automatically replayed after 401.

### Fixed

- QML root load failures now fail initialization instead of being logged as success.
- PFFFT scratch is aligned, per-call, immutable-setup backed, and protected from reset/analyze races; deterministic silence is returned on setup failure.
- Audio callback scratch is preallocated; oversized buffers are dropped without allocation.
- FBO, playlist, preset, database, theme, and config persistence failures now produce actionable logs.
- Cached QML bridge statics and application shutdown lifetimes are cleared in dependency order.
- Unit tests no longer write temporary playlists into the real user session file.

### Changed

- `version.txt` is the single source of truth for the CMake project, application version, and CPack version; invalid values fail configuration.
- Added the MIT `LICENSE` file referenced by the README/PKGBUILD and aligned the Arch package to `v1.1.0`.
- PFFFT is pinned to the tested revision; declaration-only Suno fetch declarations and stale legacy API surfaces are removed.
- Library search is explicitly local; the captured feed filter is not extended with unobserved `searchText` behavior.

### Verification

- 8/8 CTest targets pass, including epoch, upload, Explore, Notifications, Clerk, AudioAnalyzer, and offscreen QML integration tests.
- QML lint completes on the current entry module.
- The rebuilt desktop executable reaches `QML window created successfully` and `Initialization complete` in a real startup smoke.
