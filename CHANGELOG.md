# Changelog

Current release: **1.1.0** — 2026-09-26

This is the canonical changelog for ChadVis. It follows [Keep a Changelog](https://keepachangelog.com/en/1.0.0/) and [Semantic Versioning](https://semver.org/spec/v2.0.0.html). Pre-pivot, oversized history is retained as [docs/CHANGELOG_LEGACY.md](docs/CHANGELOG_LEGACY.md). That file predates version normalization in its `2.1.0`/`2.0.0`/`1.1.0`/`1.0.0` sections, but it also opens with a post-normalization `[Unreleased]` block that carries most of the work now published here as 1.1.0 — so the legacy file overlaps this one rather than being purely historical.

## [Unreleased]

### Added

- A GL-backed integration suite for the recording pipeline, registered as its own `integration_gl_tests` ctest entry. It runs against a real window, context and projectM, and proves the destination projectM actually draws into, that a bound FBO is ignored, that the capture is non-empty and correctly oriented, that a differing record resolution is scaled, that the live native window captures pixels through its own render timer and buffer swap, and that a 45-frame H.264 encode decodes back to a lit picture. The headless `integration_tests` entry still runs offscreen, where these skip with a stated reason — the macOS offscreen QPA plugin cannot create an OpenGL context at all, so a green headless run would prove nothing.

### Fixed

- **A dropped frame silently sped up the recording.** `VideoRecorderFFmpeg::encodeVideo` discarded the per-frame capture timestamp it had been handed and assigned `pts = videoFrameCount_++`, which assumes every rendered frame was encoded. `FrameGrabber::pushFrame` drops the oldest frame when its queue is full, so after a drop the remaining frames were renumbered contiguously and the segment played faster than real time with no audio-locked correspondence. PTS now derives from the frame's own capture time, so the gap falls out of the data rather than being synthesised, and the counter is deleted. Three decisions are load-bearing: `av_rescale_q` rather than a hand-rolled division, because truncating biases every frame one tick early *and* accumulates while nearest-integer is bounded by half a tick with no drift; the origin is normalised to PTS 0, because a `steady_clock` reading is microseconds since boot and handing that to a muxer inflates the reported duration through the MP4 edit list; and monotonicity is guaranteed twice over, by a `lastVideoPts_ + 1` floor and by a no-timestamp path that steps by the last observed real interval rather than acting as a counter, so extrapolation error cannot accumulate. **Stated limitation:** when the renderer outruns the nominal record fps, consecutive frames collapse to one tick and duration tracks frame count rather than wall time — pre-existing behaviour, unchanged, and already the subject of a `startRecording` warning; fixing it is frame-rate conversion. Five tests read the **finished file** back through `avformat_open_input` rather than a seam, because a worker pops one frame per loop iteration and a deliberate drop could not otherwise be positioned. The discriminating one requires 11 frames to land on exactly the tick set `{0..11}\{4}`; the old counter produced `{0..10}` with uniform steps. Also fixed: `EncoderSettings::validate()` never checked `video.fps`, so a directly-constructed settings object could reach a `{1,0}` time base and divide by zero — unreachable from config, which clamps to `[10,120]`, but now fail-closed in `initVideoStream`.
- **`LyricsBridge::getUpcomingLines` had the same signed-overflow shape already fixed in `getContextLines`, in the adjacent function.** The window was computed as `start + count` with `count` arriving from QML as a signed `int`, so a large count wrapped the end index negative and the function returned an **empty list** where the answer is the rest of the song; and `currentLineIndex_ + 1` wrapped at `INT_MAX`, so a query for a line that cannot exist answered with the entire song. The window is now a distance to the last line, the anchor is chosen from the bounds rather than by addition, and every subscript routes through the same `checkedIndex` gate — so there is now exactly one bounds gate across the whole lyrics query path. A related finding is recorded rather than papered over: the bridge and `LyricsSync` diverge at the anchor in **opposite directions** between the two functions, so delegating `getUpcomingLines` to `LyricsSync` would silently drop line 0 from the pre-render buffer. Both agreements and both single disagreements are now pinned by tests, along with the differing signatures (`int` vs `size_t`), so neither can be "fixed" into the other by accident.
- **`Signal::emitSignal` could clear its own re-entrancy guard.** A slot may emit the same signal again — the layered bridges make that easy — and with `emitting_` as a plain `bool` the inner emit's reset cleared the flag the outer one still depended on, so the outer emit's remaining `disconnect` calls took the immediate-erase path against the live connection list while the outer loop was still iterating its snapshot. It is a depth counter now, with an RAII guard so a throwing subscriber cannot strand the chain at a non-zero depth and silently disable deferred cleanup for the rest of the signal's life. A slot *can* throw here — several subscribers allocate, and one re-emits a Qt signal carrying the moved frame buffer — and the stranded counter on a throw is pre-existing, not introduced by the counter. The per-emit sweep is now gated on a flag only a real disconnect sets, so the 60 fps path no longer walks the connection list on every frame. Two new tests fail on the previous code: one drives a nested emit and asserts the chain is not swept out from under the outer emit, the other throws from a subscriber and asserts the chain is still usable afterwards.
- **The recording-side FFmpeg context deleter was duplicated in a test, with a comment asserting a rule that had stopped being true.** `test_ProjectMFramebuffer.cpp` carried its own `InputFormatDeleter` plus a note that the shared deleter was write-side-only — false since the input alias was introduced. It now uses `AVFormatContextInPtr`, so the reader/writer rule has exactly one owner, and `<memory>` is correctly retained for an unrelated smart pointer in the same file.
- **`VisualizerWindow`'s native fullscreen path was dead code that was not harmless.** Once fullscreen moved to the QML window, the C++ `toggleFullscreen`, its `fullscreen_`/`normalGeometry_` state, the `F`/`F11`/`Escape` key branches and the whole `mouseDoubleClickEvent` override were unreachable — the window is a `QQuickWindowContainer` child, so it is never top-level and never receives a key. The premise that deleting it was a free cleanup was wrong in a way that justified the deletion: the double-click *was* the one path that still fired, and it latched `fullscreen_ = true` permanently while fighting the container's layout sync and leaving the QML chrome on screen. All of it is deleted, with the constraint documented as a class-level `@section Embedding` note so it is not re-added. `keyPressEvent` itself is **kept** — it still carries preset bindings whose `R`/`L` branches have no QML equivalent, so removing them on the same inference would have been a silent capability loss. The double-click gesture is consequently gone; `F`/`F11` is the supported way in.
- **Four repository config files read as coverage and delivered none.** `.clang-format` demanded Allman braces against an entirely attached-brace tree, so it flagged untouched files; it is regenerated from the code (attached braces, 4-space indent, continuation 8, 100 columns, Qt-first include ordering) and violations across 15 representative untouched files fall from 946 to 423. `.clang-tidy` was a verbatim LLVM copy-paste whose naming rules wanted `CamelCase` with no trailing underscore, which is where its false positives came from; every key is now re-derived from this tree's actual convention and the `modernize`/`bugprone`/`clang-analyzer`/`concurrency`/`performance`/`portability` families are enabled, with 21 noisy checks disabled each with a stated reason. **The reason it had never been run at all is not a config defect:** the compile database records Apple clang's command with no `-isysroot` and no libc++ path, and Homebrew's clang-tidy does not infer the SDK — so the error's own file path was the evidence that only libc++ and the SDK were missing, not Homebrew's include root. The working invocation is documented in the file header. The proper fix belongs in `cmake/` and is not done. `.prettierignore` is deleted (no prettier setup existed, and its only content was a file from another project); `dependabot.yml` is restricted to `github-actions`, the one ecosystem it can actually serve, and says so rather than implying it can see the CMake pins.
- **The QML version strings never tracked `version.txt`, and disagreed with each other.** `main.qml` rendered `v2.0.0 · Suno Desktop` and `NavRail.qml` rendered `v2.0` while the real version is `1.1.0` — two different wrong values in two files, neither ever wired to the build. A closed backlog item claimed the banner consumed `CHADVIS_VERSION`; that was true only in C++ (`test_Version.cpp` pins the CLI banner and `--version` to `version.txt`) and the QML layer was never converted. Both sites now bind to a `CONSTANT` `SettingsBridge.version` off the existing `CHADVIS_VERSION`, with no new version source and no registration change. The `v` prefix and the `· Suno Desktop` suffix are preserved. A source-scan test now fails if any QML string literal looks like a version again, and a second test asserts both sites still bind, so "no literal" cannot be satisfied by deleting the version display.
- **`classifyStoredCredential` rejected cookie jars Clerk actually writes.** It required an *exact* name of `__client` or `__client_uat`, but Clerk instance-suffixes the name — the 2026-08-25 capture has `__client_Jnxw-muT` and `__client_uat_Jnxw-muT` on the wire — and `__session` is the actual access-token cookie. A jar carrying only the suffixed pair, or only `__session`, was rejected with a generic unsupported-credential message. Matching is now a prefix test against `__client_uat` / `__client` / `__session`, and the diagnostic names *which* cookie names it saw, so "wrong cookie" and "no cookie at all" are distinguishable. Because a name arrives from a user paste it is treated as untrusted: names are quoted, values never are, and a name failing a charset check or over 64 chars is counted rather than reproduced. Nothing forwarded to the network changed — the classifier is a shape test, not a sufficiency test. An existing test case had pinned the buggy behaviour as intended (`__session`-only → `Unsupported`); it is flipped and renamed. **Deliberately left open:** whether a jar carrying only `__client_uat` *should* be sufficient, since the inventory documents that cookie as non-secret session-presence metadata. That needs a capture, not an inference.
- **Dead duplicate SRT/LRC formatters deleted.** `LyricsData::toSrt`/`toLrc` had zero callers and shadowed `LyricsBridge::exportToSrt`/`exportToLrc`, so two formatters existed where one is correct; removing them also removed the file's only `snprintf` calls and its only `std::ostringstream`. A test now pins the live bridge's exact output bytes, so a second formatter reappearing fails. The original claim that the export tests exercised the *dead* implementation was wrong — they already drove the live path.
- **`LyricsSync::getContextLines` had an infinite loop on an oversized window.** Its "after" loop was `for (size_t i = 1; i <= after; ++i)`, which never terminates when `after == SIZE_MAX`; the "before" loop separately spun up to 2^31 iterations for a large `before`, all of which were then rejected. Both are now bounded by the real last-line index with bit-identical result ordering, and a regression test times out on the old code rather than passing it. Latent in production only because these methods have no production callers — the QML-reachable query is `LyricsBridge`'s.
- **`LyricsBridge::getContextLines` could overflow its window arithmetic.** `center + after + 1` with a large `after` overflowed `int`, the end index wrapped negative, and the function silently returned an **empty list** where the correct answer is the whole song. The window is now measured as a distance to the first/last line, and the hand-rolled cast is replaced by the same `checkedIndex` gate the rest of the lyrics path uses. Found by a test written to compare this query against `LyricsSync`'s; that comparison also pinned the one place the two legitimately differ, the anchor rule, and a second test proves an unattached `LyricsSync` still yields nothing rather than crashing.
- **`AVFormatContextDeleter` segfaulted any attempt to read a file.** It dereferenced `c->oformat->flags`, and a demuxer's `oformat` is null, so decoding a recording in a test crashed on `0x2c`. Split into `AVFormatContextInPtr` (`avformat_close_input`) and `AVFormatContextOutPtr` (`avformat_free_context`), with the old alias deleted so a stale reference is a compile error. The `AVFMT_NOFILE` check was wrong on both sides and was replaced by `AVFMT_FLAG_CUSTOM_IO`, which lives on `c->flags` and so cannot reintroduce the null-`oformat` class of bug. The output side still closes the `AVIOContext` it owns, which `avformat_close_input` would otherwise double-close. Five tests added; the regression guard writes a real WAV, asserts the exact `iformat != nullptr` / `oformat == nullptr` state that killed the old deleter, reads a packet and releases.
- **A QML text field could swallow the fullscreen shortcut, and the shortcut did nothing when it did not.** `main.qml` revealed the Video page and logged a TODO; separately, the C++ handler for `F`/`F11`/`Escape`/double-click lives on `VisualizerWindow`, which is **never shown** — it exists only as a `QQuickWindowContainer` child, so its `keyPressEvent` can never see a key and its `showFullScreen()` is inert. The defect was not a missing binding but a handler pointed at the wrong window. Fullscreen is now the QML `ApplicationWindow`, for two independent reasons: the native window's fullscreen request is inert, and the nav rail, header, overlay and karaoke layers are QML *siblings* that would stay on screen regardless. `F` and `F11` are two bindings for one action rather than a fallback — `F11` is unconditional, which is what keeps fullscreen reachable while typing, because no text field consumes a function key as text; `F` stands down during text entry, detected by walking `activeFocusItem` and three ancestors so both focus models are covered. Fullscreen state is *derived* from `visibility` rather than stored, so a window-manager exit cannot desync it. **Not verified by test and cannot be:** fullscreen needs a real window and a GL-capable QPA plugin; a nine-step manual pass is recorded in the work log.
- **`Signal::emitSignal` copied the whole frame per subscriber, per frame.** The signature took the payload by value and passed it on as an lvalue, so a 1920x1080 frame meant ~8 MB of memcpy per frame on the GUI thread, immediately after a GPU readback that already cost the same. It is now a deduced forwarding reference, with the last active subscriber taking the forwarded value and earlier ones a copy of the still-intact payload. **The fix is narrower than the original claim suggested, and the reason is worth recording:** `frameCaptured` has exactly one production subscriber, so the hot path takes the forwarded branch and now pays *zero* copies. `Slot` was deliberately left alone — `std::function`'s by-value parameter is a real copy boundary, but removing it would buy one 24-byte move while introducing a dangling-reference hazard across ~30 connect sites and breaking the reference payload types. The defect was always measured in *bytes*; the test suite that first "verified" this asserted construction counts instead, which made a 24-byte buffer steal look equivalent to an 8 MB copy. The centrepiece test now asserts buffer **aliasing** — identical `data()` pointer plus an emptied source capacity — which fails if a by-value hop is reintroduced anywhere in the chain and is robust across standard libraries. Two defects introduced along the way were fixed: an `assert` guarding non-copyable fan-out **compiled out under `NDEBUG`**, and the distributable build is Release, so that was a release-only silent-corruption path, now a `static_assert` at the class declaration; and the deduced pack stopped type-checking call sites, so a wrong-typed call failed deep inside `std::function` naming the subscriber's lambda, now a `static_assert` on pack size and convertibility.
- Two out-of-bounds reads in the lyrics path, both reachable from QML. `LyricsData::getTimeRange` clamped only the low end of `startIdx` and let a caller-supplied `size_t` near `SIZE_MAX` wrap `endIdx - 1` into a catastrophic subscript; both indices are now saturated against real bounds. `LyricsSync::getContextLines` checked only the lower bound on the cached `currentPos_.lineIndex`, so loading a shorter song left a stale index that a subsequent query read past the end. A shared `constexpr checkedIndex()` helper replaces the ad-hoc `int`/`size_t` mixing at the QML bridge boundary that allowed both to survive. `onPlaylistCurrentChanged` is bound to `currentChanged`, which fires for every index change, and it called `play()` unconditionally, so a user skip or a queue edit resumed a paused transport; `autoPlayNext_` guarded only the automatic end-of-track advance. That one advance is now granted explicitly by the end-of-media handler instead of being inferred from the transport state, because Qt makes no promise about whether the player has already reported `StoppedState` by the time `EndOfMedia` arrives. Three tests drive a real generated WAV through the engine: a skip while paused stays paused (mutation-checked against the old behavior), a skip while playing keeps playing, and a track playing to its end advances into the next one — the last skips on a machine whose audio backend reports `Playing` without advancing the playhead, and says so rather than claiming a pass.
- Shuffle with repeat-off skipped a track, and enabling it did not shuffle where playback started. `next()` pre-incremented the shuffle position even with nothing selected, stepping past the first entry of the permutation, and `play()` pinned the first selection to the first queued item — which lands mid-permutation, so the entry before it could not be played in that pass. A shuffle pass is now a permutation walk that starts at its first entry and covers every track exactly once, via a single named `Playlist::startPlayback()`. `addFile` also appends to the shuffle order the way `addUrl` already did, instead of splicing the new track in at a random position, which had been moving entries underneath the traversal and could make a pass play one track twice while skipping another.
- The audio engine ran a dedicated analyzer thread that performed a PFFFT analysis every 2048 samples and emitted a 1 KB spectrum to a signal with no receivers, and `currentPCM()` had no callers either. Both are gone, along with the third `AudioQueue` queue that existed only to feed that worker: with its sole consumer removed it could only fill and drop, so `pushAll` now feeds the visualizer and recorder queues. `AudioAnalyzer` itself is kept — it is a standalone component with its own tests, and giving it a reader is a feature rather than a cleanup.
- **Recorded video was a transparent-black buffer, and starting a recording painted that emptiness over the live visualizer window.** projectM v4 has exactly one render destination: it binds framebuffer 0 for its closing texture copy, next to the upstream note "ToDo: Allow external apps to provide a custom target framebuffer". The renderer bound its own FBO, so projectM never wrote a pixel into it and the capture read back nothing but that FBO's `glClearColor(0,0,0,0)`. Nothing caught it because the recorder tests submit synthetic buffers without rendering anything, and the two classes that could have grabbed real pixels (`FrameGrabber::grab`/`grabScreen`) were called by nothing. Measured before the fix, with an FBO bound as the draw target across 30 rendered frames: **0 non-zero bytes in the FBO, 262 107 in the default framebuffer**; the renderer's own capture path measured **0 of 262 144**. `renderFrame` now renders projectM straight into framebuffer 0 under a scissor box and reads the recording back out of the same buffer, so the live view and the encoded file are the same pixels. A recording resolution that differs from the window's is a readback scale, not a different render target. Measured after: the capture carries 262 088 of 262 144 bytes, the live native window captures 261 972, and a real 45-frame H.264 MP4 decodes to a 256x256 stream whose brightest frame has 65 337 lit luma pixels. The `useFBO` branch, the blit shader/program/VAO/VBO, `flipImageGPU`, `Engine::renderToTarget`, `FrameGrabber::grab`/`grabScreen` and the dead `RenderTarget` readback helpers are deleted rather than left as traps.
- **Recorded video was upside down.** `glReadPixels` returns rows bottom-up and the encoder uploads them as they arrive, and the live capture applied no flip at all — the correct CPU implementation sat dead behind a `useGPUFlip_` branch nothing could reach. `FrameGrabber::flipImage` is now a public static applied to every mapped PBO before the frame is emitted, with three unit tests and an integration test that compares an emitted frame against a raw readback of the *same* frame. Mutation-checked: removing the single call fails exactly that test, with the non-emptiness test still green.
- Starting a recording could no longer resize the render target to a zero or odd resolution, and now warns loudly when the recording frame rate disagrees with the visualizer's instead of silently writing a retimed file. `targetFps_` finally tracks the real render rate.
- `chadvis-projectm-qt --version` reported a hardcoded `1.0.0` while the build was `1.1.0`. The banner is now assembled by `vc::Cli::versionBanner()` from the `CHADVIS_VERSION` definition that `version.txt` feeds, and `tests/unit/core/test_Version.cpp` pins the banner text and the real executable's `--version` output to `version.txt`, so a reintroduced literal fails the suite.
- Two out-of-bounds reads in the lyrics path, both reachable from QML. `LyricsData::getTimeRange` clamped only the low end of `startIdx` and let a caller-supplied `size_t` near `SIZE_MAX` wrap `endIdx - 1` into a catastrophic subscript; both indices are now saturated against real bounds. `LyricsSync::getContextLines` checked only the lower bound on the cached `currentPos_.lineIndex`, so loading a shorter song left a stale index that a subsequent query read past the end. A shared `constexpr checkedIndex()` helper replaces the ad-hoc `int`/`size_t` mixing at the QML bridge boundary that allowed both to survive.
- `TestSunoEndpoints` and `TestPresetScanner` were compiled into `unit_tests` but never executed — the fail-closed host-allowlist guard had never actually run. Both are now registered in `test_main.cpp`; the static initializer that called `std::abort()` to make the endpoints test noticeable is removed.
- A rescan request arriving between the preset worker posting its result and the publishing thread applying it started a second concurrent walk, because the in-flight state was only a `requested || running` pair and `running` was already cleared. That let a burst of rescans multiply directory walks and `presetsChanged` rebuilds. A third state now spans the post-to-apply window and is taken into account when deciding whether to coalesce, so a scan is considered in flight continuously from request through publication. The test assertion that accompanied it claimed "eight requests produce at most two notifications", which was never a guarantee — coalescing bounds concurrency, not the total number of walks — and it flaked at roughly 1 in 30. It now asserts the real invariant. 60 consecutive runs clean.
- `Playlist` exposed `items()` as a live `const std::vector&` plus `currentItem()`/`itemAt()` as raw pointers into that vector, so every read path held a reference or pointer into mutable storage. The read API now returns values: `itemAt()`/`currentItem()` give `std::optional<PlaylistItem>`, and `snapshot()` gives an owned list. `items()` is gone.
- `MediaMetadata::albumArt` was a `std::optional<QPixmap>` written on every add and read by nothing. Besides a full image decode per file on the GUI thread, it made `PlaylistItem` un-movable across a thread boundary, since a `QPixmap` must be both created and destroyed on the GUI thread.
- Every playlist mutation wrote the whole session playlist to disk synchronously, and `addFile` emits once per file, so dropping 200 files performed 200 full M3U writes on the GUI thread. Now debounced 500 ms, flushed on destruction.
- `removeAt` and `clear` moved the current index without emitting `currentChanged`, so the engine kept playing a removed track and never recomputed its pre-buffer. The signal payload is now `std::optional<usize>` — `Signal<usize>` could not express "no current item", which is why those call sites had gone silent.
- Dead audio plumbing removed: `pcmReceived` was emitted from the audio thread copying a `std::vector<f32>` per callback with zero receivers, and `currentSpectrum()` had no callers. `spectrumUpdated` likewise has none, so `currentSpectrum_` is now written once per analyzer tick for nothing.
- Fixed a latent build break: `rng_(std::random_device{})` does not compile under libc++ ("expects an lvalue for $1"). The checked-in static library had been built with a different toolchain and `ninja: no work to do` hid it, so any clean rebuild would have failed.

## [1.1.0] - 2026-09-26

This release finalizes the `v1.1.0-BLEEDING_EDGE` line and is the first version whose source, executable, and release metadata are sourced from the same `version.txt` value.

### Added

- Suno-first desktop shell with Library, Create, Listen, Video, and standalone paged Settings surfaces.
- Capture-backed Explore, Notifications, Library pagination/filtering, account/billing surfaces, and the captured three-leg `.m4a` upload transport.
- End-to-end captured aligned-lyrics karaoke: authoritative playback handoff, active-clip gating, late-load synchronization, Listen/Video highlighting, SRT/LRC export, local search, and context/upcoming queries.
- Native visualizer window visibility toggle.
- Offscreen QML integration smoke that requires a visible/exposed root and a non-null rendered frame.
- Focused epoch, media/origin, header, persistence, and audio-concurrency regression coverage.

### Security

- Credential/request epochs fence queued work, retries, auth waiters, and tracked replies across sign-out, replacement, and auth loss; direct uploads cancel on credential invalidation.
- Settings credential ownership is centralized in `SunoClient`; manual edits are debounced off the GUI thread and clearing keeps memory and durable storage coherent.
- Remote artwork, MP3 media, and direct upload URLs are restricted to exact capture-proven HTTPS origins with manual redirects.
- Clerk session selection requires an exact `last_active_session_id` match; undocumented Browser-Token synthesis and automatic `/tokens` fallback are disabled.
- Mutation POSTs are not automatically replayed after 401.

### Fixed

- QML root load failures now fail initialization instead of being logged as success.
- PFFFT scratch is aligned, per-call, immutable-setup backed, and protected from reset/analyze races; deterministic silence is returned on setup failure.
- Audio callback scratch is preallocated; oversized buffers are dropped without allocation.
- FBO, playlist, preset, database, theme, and config persistence failures now produce actionable logs.
- Cached QML bridge statics and application shutdown lifetimes are cleared in dependency order.
- Unit tests no longer write temporary playlists into the real user session file.

### Changed

- `version.txt` is the single source of truth for the CMake project, application version, and CPack version; invalid values fail configuration.
- Added the MIT `LICENSE` file referenced by the README/PKGBUILD and aligned the Arch package to `v1.1.0`.
- PFFFT is pinned to the tested revision; declaration-only Suno fetch declarations and stale legacy API surfaces are removed.
- Library search is explicitly local; the captured feed filter is not extended with unobserved `searchText` behavior.
- Unpromoted Range resume and redirect following remain disabled until capture-backed.

### Verification

- 8/8 CTest targets pass, including epoch, upload, Explore, Notifications, Clerk, AudioAnalyzer, and offscreen QML integration tests.
- QML lint completes on the current entry module.
- The rebuilt desktop executable reaches `QML window created successfully` and `Initialization complete` in a real startup smoke.
- AudioAnalyzer concurrency tests pass under ThreadSanitizer.
